# מתכון הגזירה הגנרית — הפיכת סוכן אישי לעותק נייד לשיתוף

> ספר-ההוראות של מצב `/genericize-agent`. הפקודה מצביעה לכאן.
> **מקור המתכון:** מבוסס על גזירות קודמות. זה ה-reference החי.
>
> **מה המצב הזה עושה:** לוקח סוכן אישי קיים (שלך) וגוזר ממנו **עותק גנרי נייד** —
> מנוקה מכל פרט אישי, מוכן לשיתוף עם אנשים אחרים (חברי קורס, לקוחות), ארוז ל-`.plugin` ול-`.zip`.
> **המקור האישי לא נגעים בו לעולם** — עובדים על עותק.

---

## עיקרון-העל של המצב: לשאול, לא לנחש (קטלוג א.5 + ד.1)

גזירה גנרית מלאה בהכרעות **רגישות** — מה לעשות עם הקדשה אישית, עם זיכרון של אדם, עם מערכות ידע פרטיות. **יכין לא מכריע אותן לבד.** הלב של המצב הוא **3 שערי-ההכרעה** (שלב 3 למטה) — עוצרים, מציגים, המשתמש/ת בוחר/ת.

כשל-העל של גזירה גנרית הוא **דליפה** — שם אישי / ארגון / מוצר ששרד בעותק "הגנרי". לכן יש **שער וידוא-ניקיון** (שלב 7) לפני האריזה. אל תדלג עליו.

## שלב 0 — איזה סוכן, ולאן הפלט הולך

**שאל (אם לא צוין):** איזה סוכן גוזרים? (נתיב תיקיית המקור, למשל `agents/ready/<name>/`.)

**מיקומי הפלט — מקובעים (אל תאלתר):**
| מה | לאן |
|---|---|
| עבודת הפיתוח (טיוטות, הנדאוף) | `agents/completed/<name>-generic-dev/` |
| המוצר הגנרי | `agents/ready/<name>-gen/` |
| קבצי היצוא | `plugin-builds/<name>-gen.plugin` + `.zip` |

> **שם ברירת-מחדל:** `<name>-gen` (סיומת `-gen` = generic). כך העותק הגנרי דָּר בשלום לצד האישי בלי התנגשות — שתי תיקיות נפרדות, שתי פקודות נפרדות.

**⚠️ הפצה — שתי שכבות, אל תבלבל ביניהן:**
- **בשיחה** הסוכן שומר את הזהות האותנטית — מילת הטריגר וההצגה העצמית זהות למקור (למשל "השם כאן."), כדי שמי שמוריד יקבל את החוויה האמיתית.
- **בקטלוג** (`marketplace.json` + הגלריה) הוא מסומן **"עותק לשיתוף"**, כדי שתבחין/י בין האישי לגנרי במבט אחד.

**כן רושמים אותו ב-`marketplace.json`** (ערך חדש עם `source: ./agents/ready/<name>-gen` + תיאור מסומן "עותק לשיתוף") — כך הוא מקבל כרטיס תקין בגלריה והופך לפריט הורדה. קבצי ה-`.plugin`/`.zip` הם ערוץ שיתוף-קובץ נוסף וישיר.

**מדיניות חשיפה בגלריה (כלל קבוע):** כל מה שעם `-gen` → **"פתוח להורדה לכולם"**; סוכנים אישיים → "חברי הקורס". (רמת החשיפה נקבעת ב-UI של הגלריה, לא ב-`marketplace.json`.)

**⚠️ את/ה עצמך לא מתקין/ה את העותק הגנרי אצלך** — אחרת הסוכן יתנגש בין האישי לגנרי (אותה מילת טריגר). הוא חי בגלריה להורדת אחרים, לא מחובר ל-Claude שלך.

## שלב 2 — מיפוי (grep לפני נגיעה)

לפני שמחליפים משהו — **ממפים מה יש.** הרץ grep על העותק לכל מה שספציפי:

התוצאה: רשימת כל המקומות שדורשים הכרעה או החלפה. **זה הקלט ל-3 השערים.** הצג למשתמש/ת מה נמצא.

## שלב 3 — 3 שערי-ההכרעה הרגישים (הלב — עוצרים, המשתמש/ת בוחר/ת)

לכל שער: הצג מה נמצא, את **האפשרויות**, ואת ה**היגיון** — ואז עצור לבחירה. אחת בכל פעם. המשתמש/ת מכריע/ה.

### שער א' — הקדשה / זיכרון אישי
המקור עשוי לשאת שורת הקדשה או זיכרון של אדם. זו ההכרעה הכי רגישה.
- **לשמור** — אם ההקדשה מתאימה גם לקהל הרחב.
- **לנטרל** — להסיר לגמרי.
- **להחליף** — הקדשה אחרת, מתאימה לשיתוף. *(למשל: ההקדשה שוּנתה להקדשה מתאימה לשיתוף.)*
> **למה שער נפרד:** הקדשה היא רגש, לא טקסט. לא מנחשים מה לעשות עם זיכרון של אדם.

### שער ב' — מערכות ידע ספציפיות
המקור מפנה למערכות/מושגים פרטיים (למשל מערכת הידע שלך, ריפו מסוים, מאגר-הידע שלך).
- **להוריד** — המערכת לא רלוונטית למשתמש אחר.
- **להשאיר כדוגמה** — "למשל מערכת כמו X" — ממחיש בלי לחייב.
- **דפוס גמיש** — להכליל ל"מערכת הידע שלך", בלי לנקוב בשם.
> **למה שער נפרד:** מערכת ידע פרטית שנשארת = העותק לא באמת גנרי, אבל הסרה עיוורת עלולה לרוקן רכיב חשוב. המשתמש/ת מכריע/ה פר-מערכת.

### שער ג' — שם טכני
- **נקי** (`<name>`) — לשיתוף עצמאי, כשאין אישי מקביל בסביבת היעד.
- **נפרד** (`<name>-gen`) — **ברירת המחדל** — לדו-קיום עם האישי באותו ריפו/מרקטפלייס.
> **למה שער נפרד:** שם זהה לאישי → התנגשות טעינה (שתי מילות-טריגר זהות). `-gen` פותר את הדו-קיום.

## שלב 4 — החלפה (ניקוי התוכן)

לפי הכרעות השערים, עבור על העותק והחלף:
- **השם האישי → פנייה גנרית:** "את/ה" / "המשתמש/ת". *(לא שם אישי → שם אחר; פנייה ניטרלית.)*
- **הסר את סעיף "מי המשתמש"** (הפרטים האישיים — שם, מקצוע, העדפות).
- **נַקֵּה דוגמאות ספציפיות** — דוגמה שמבוססת על העסק/הארגון של המשתמש/ת → דוגמה גנרית או פלייסהולדר.
- **תובנות-על על המשתמש/ת** (אם הסוכן נשען עליהן) → הכלל או הסר; הן על המשתמש/ת המקורי/ת, לא על משתמש אחר.

**⚠️ מוקש — הדוגמאות הקוליות:** אל תנקה רק את הטקסט התיאורי. נקה גם את **הדוגמאות בקול הסוכן** (משפטים שהסוכן "אומר"). דוגמה בלשון נקבה → בסיס ניטרלי עם לוכסן ("בוא/י", "שלך"). את זה כמעט מפספסים.

## שלב 5 — שכבת שמות (טכני נפרד מחוויתי)

**הפרד שתי שכבות:**
- **טכני** (אנגלית) — השם `<name>-gen` בכל מקום שהוא **מזהה**.
- **חוויתי** (עברית) — **נשמר כמו במקור:** מילת הטריגר בעברית וההצגה-העצמית של הסוכן. *(האישי והגנרי שניהם מציגים את עצמם באותו שם ונטענים על אותה מילת טריגר — רק השם הטכני נבדל.)*

**⚠️ כלל-ברזל (למדנו בדם מגזירות קודמות) — תיקיית ה-skill הראשית חייבת להיות זהה לשם הפלאגין:**

הגלריה שואבת את כרטיס הסוכן (כותרת, תיאור, סוג) מ-**`skills/{שם-הפלאגין}/SKILL.md`**. אם התיקייה לא נקראת בדיוק כמו שם הפלאגין — הגלריה לא מוצאת אותה, והכרטיס יוצא שבור ("אין תיאור זמין" + שם באנגלית).

| משנים ל-`<name>-gen` | משאירים כמו במקור |
|---|---|
| `plugin.json` → `name` | תיקיות ה-skill ה**משניות** (`pirur-libniya`, `seder` וכו') |
| כל `SKILL.md` → שדה `name:` | מבנה התיקיות הפנימי האחר |
| שם **קובץ** הפקודה (`commands/<name>-gen.md`) | |
| שורת "הפעל את skill `<name>-gen`" שבפקודה | |
| **★ תיקיית ה-skill הראשית** (`skills/<old>/` → `skills/<name>-gen/`) | |
| **★ ההפניה אליה** (`${CLAUDE_PLUGIN_ROOT}/skills/<name>-gen/SKILL.md`) | |

> **למה:** שם הפלאגין הוא מזהה — שניים זהים במרקטפלייס מתנגשים, לכן משנים. אבל ה-skill הראשי אינו "נתיב פיזי אדיש" — הגלריה **מחפשת אותו לפי שם הפלאגין**. לכן `plugin.json → name = <name>-gen` מחייב `skills/<name>-gen/` (ולא `skills/<name>/`). תיקיות ה-skill ה**משניות** לא צריכות להתאים — רק הראשית. **טעות היסטורית:** גרסה קודמת של המתכון אמרה "אל תשנה שמות תיקיות" — זה היה מבוסס על עותק שנראה תקין אבל היה שבור בגלריה בדיוק בגלל זה.

העותק הגנרי לא יודע מי מולו. הטמע רכיב פנייה:
- **בהיכרות הראשונה** הסוכן שואל את המשתמש/ת אם לפנות בלשון זכר או נקבה, ומדבר בלשון שנבחרה מכאן ואילך.

- ההעדפה שנבחרה נרשמת (בפתק המעבר / זיכרון הסוכן) כדי שלא ישאל שוב.

> זה רכיב שנולד בגזירות קודמות ושווה בכל עותק גנרי — סוכן אישי יודע את המגדר מראש, גנרי לא.

## שלב 8 — אריזה (פלט כפול: `.plugin` + `.zip`)

**כל פעולה יקרה — אישור לפני.**

`.plugin` הוא **zip** (זהה בייט-בבייט; רק הסיומת שונה). אורזים פעם אחת, שומרים בשני שמות.

**⚠️ מוקש Windows — אל תשתמש ב-`zip -r` וב-`Compress-Archive`:**
- `zip` לא קיים ב-Git Bash של Windows.
- `Compress-Archive` יוצר נתיבים עם `\` — **שוברים התקנה ב-Mac.**
- הפתרון: `System.IO.Compression` עם **החלפת `\`→`/`** בשמות ה-entries.

**הקוד הבדוק (PowerShell):**
```powershell
$name = "<name>-gen"
$src  = "<repo-root>/agents/ready/$name"
$outDir = "<repo-root>/plugin-builds"
$plugin = "$outDir/$name.plugin"

Add-Type -AssemblyName System.IO.Compression.FileSystem
New-Item -ItemType Directory -Force $outDir | Out-Null
if (Test-Path $plugin) { Remove-Item $plugin -Force }

$zip = [System.IO.Compression.ZipFile]::Open($plugin, 'Create')
Get-ChildItem -Path $src -Recurse -File |
  Where-Object { $_.Name -ne '.DS_Store' } |
  ForEach-Object {
    $rel = $_.FullName.Substring((Resolve-Path $src).Path.Length + 1) -replace '\\','/'
    [System.IO.Compression.ZipFileExtensions]::CreateEntryFromFile($zip, $_.FullName, $rel) | Out-Null
  }
$zip.Dispose()

Copy-Item $plugin ($plugin -replace '\.plugin$','.zip') -Force
```

**אמת אחרי האריזה:** פתח את ה-zip ובדוק ששמות ה-entries משתמשים ב-`/` (לא `\`), ושכל הקבצים בפנים.

**דיווח למשתמש/ת:** נתיב שני הקבצים, גודל, ורשימת מה שנכלל.
