# הקאנון הטכני — איך בונים סוכן בריפו שלך

> מזוקק מסוכנים קיימים. זה ה"איך" הטכני שיָכִין נשען עליו בשלבים 2 ו-4.
> **עיקרון-על: כל הנתיבים/שמות-הקבצים באנגלית. רק תוכן הקבצים בעברית.** (קטלוג ו.4)

---

## 1. מבנה תיקיית סוכן

```
agents/ready/<name>/                  ← בפיתוח: agents/in-progress/<name>-dev/
├── .claude-plugin/
│   └── plugin.json                   ← זהות הפלאגין (חובה)
├── skills/<skill-name>/
│   ├── SKILL.md                      ← זהות + ניתוב (חובה)
│   └── references/                   ← שכבות הידע (.md)
│       └── *.md
├── commands/
│   ├── <mode>.md                     ← פקודת slash לכל מצב (רק לסוכן רב-מצבים)
│   └── rebuild-plugin.md             ← חובה לכל סוכן ב-ready (קטלוג ה.7)
├── system-prompt.md                  ← זהות הסוכן (חובה) — מקור לכרטיס בגלריה + התקנה כ-Project
├── README.md                         ← מה הסוכן, איך מפעילים
└── CHANGELOG.md                      ← אופציונלי, לגרסאות
```

**⚠️ `system-prompt.md` חובה:** גלריית התוצרים קוראת אותו (כותרת = ה-H1; תיאור ותגית נגזרים מהגוף). סוכן בלעדיו מופיע בגלריה פגום (שם גולמי, בלי תיאור). הוא גם קובץ-הזהות להתקנה כ-Project. תוכנו מגבש את זהות הסוכן — מקביל ל-`SKILL.md` (זהות + ניתוב לטעינה).

**חד-skill:** רק `skills/<name>/` אחד, בלי `commands/<mode>.md`.
**רב-מצבים:** SKILL ראשי + `commands/<mode>.md` לכל מצב (+ אופציה skill נפרד למצב).

**איפה יושב הידע — סטנדרט אחד (חשוב):** **הכל ב-`skills/<name>/references/`** — כולל עותקי הקטלוג והפרופילים. כך הכל **בתוך ה-skill ונוסע עם הפלאגין.** (ריפואים ותיקים לא תמיד עקביים — יש סוכנים ששמו ידע ב-`master-library/` או ב-`knowledge/` — אל תחקה; השתמש ב-`references/`.)

**⚠️ עותקים מוטמעים = צריכים סנכרון (קטלוג: כלל ה-`/sync`):** מה שמועתק לתוך `references/` הוא *עותק*; המקור-לעריכה חי בשורש הריפו:
- `agent-design-patterns.md` ← מקור: `agent-kit/agent-design-patterns.md`
- `design-profile.md` + `ux-decision-profile.md` ← מקור: מאגר-הידע שלך

עדכון במקור → **חובה להעתיק לעותקים** (אחרת הסוכן יקרא גרסה מיושנת). זה קריטי במיוחד כי שלב 3ה מגדיל את הקטלוג בשורש — אחרי הוספת רכיב, סנכרן את העותק.

## 2. `.claude-plugin/plugin.json`

```json
{
  "name": "<name>",
  "version": "1.0.0",
  "description": "<שם> — משפט אחד מה הסוכן עושה, בעברית.",
  "author": { "name": "<שמך>" },
  "keywords": ["partner-agent", "hebrew", "rtl", "<תחום>"]
}
```

- `name` — אנגלית, lowercase, ייחודי בריפו. **זה גם שם קובץ ה-.plugin.** אם השם העברי תפוס בסוכן/דמו אחר — תן name ייחודי (למשל בהוספת סיומת מבחינה).
- `version` — מתחיל `1.0.0`. שינוי משמעותי → עלה גרסה.

## 3. `SKILL.md` — שלד

```markdown
---
name: <skill-name>
description: >
  <שם> — <מה עושה במשפט>. <מסלול/מצבים>. הפעל כשהמשתמש/ת כותב/ת "<טריגר1>",
  "<טריגר2>", ... או כל בקשה ל<תחום>.
version: 1.0.0
---

> **השם שלך: <שם>.** בתגובה הראשונה של כל שיחה כתוב "<שם> כאן." כשורה ראשונה.
> קבצי הידע ב-`references/`: ...

# <שם> — <תת-כותרת>

> **השם שלך: <שם>** — <משמעות מקראית שמהדהדת את התפקיד>.

## מי אתה
<אופי + כללי-התנהגות, כל אחד מסומן ברכיב-קטלוג>

## שלב 0 — רקע לפני עבודה (קטלוג ה.4)
<קריאת CLAUDE.md + פרופילים + ידע ייעודי>

## <המסע / המצבים>
<טבלת שלבים או תפריט מצבים>

## ניתוב ידע (קטלוג ה.2)
<טבלה: מתי → איזה reference>

## כללי-ברזל 🔒
<הרשימה>
```

**עיקרון כתיבה: SKILL רזה (קטלוג ה.2).** ה-`SKILL.md` נשאר קצר וניתובי — זהות, מסע/מצבים, טבלת ניתוב, כללי-ברזל. הידע הכבד (פירוט שלבים, קאנון, דוגמאות) יושב ב-`references/` ונטען לפי-צורך. SKILL מנופח = הסוכן טוען הכל מראש ומאבד מיקוד.

## 3א. `commands/<mode>.md` — שלד פקודת-מצב (לסוכן רב-מצבים)

```markdown
---
description: <משפט קצר — מה הפקודה עושה>
---

הפעל את skill `<skill-name>`.

1. הכרז בתגובה הראשונה: "<שם> כאן."
2. טען `${CLAUDE_PLUGIN_ROOT}/skills/<name>/references/<doc>.md` — הידע למצב הזה.
3. <צעדי המצב>
```

- `${CLAUDE_PLUGIN_ROOT}` — משתנה שמצביע לשורש הפלאגין; השתמש בו לכל נתיב פנימי (לא נתיב יחסי שביר).
- פקודה = מסלול-כניסה מהיר למצב. שם הקובץ (`<mode>.md`) = שם פקודת ה-slash.
- **בדוק שם-פקודה ייחודי** — `/review` למשל תפוס (פקודת Claude Code מובנית + סוכנים אחרים). חדד לשם ייחודי (`/review-agent`).

## 4. כתיבת `description` (הטריגרים) — הקריטי ביותר

ה-`description` הוא **מה שמפעיל את הסוכן.** description חלש = הסוכן לא נטען.

- **כלול:** מה הסוכן עושה במשפט + רשימת מילות-הפעלה **בעברית ובאנגלית** + "או כל בקשה ל...".
- **טריגרים = איך המשתמש/ת *באמת* יכתוב/תכתוב**, לא מונחים טכניים. ("תבנה סוכן", לא "instantiate agent").
- **בדיקת התנגשות (חובה):** עבור על ה-`description` של כל סוכן ב-`.claude-plugin/marketplace.json` **וגם** על סקילים/פלאגינים מותקנים שאינם במרקטפלייס (שחיים כסקילים נפרדים). אם מילת-הפעלה זהה מופיעה בשניים — הסוכן הלא-נכון עלול להיטען. חדד עד שאין חפיפה, והוסף שורת-הבחנה מפורשת ("ההבדל מ-X: ...").
- **הבחנה מפורשת** מסוכן דומה ("ההבדל מ-X: ...") עוזרת לניתוב.

## 5. `commands/rebuild-plugin.md` — תבנית (חובה ל-ready)

פקודה שאורזת את תיקיית הסוכן לקובץ `.plugin` נייד. frontmatter + 4 שלבים:

```markdown
---
description: "בנייה מחדש של הפלאגין (ייצור קובץ .plugin נייד)"
allowed-tools: Read, Write, Bash, Glob
---
```
1. **אימות** — ודא `.claude-plugin/plugin.json`; שלוף `name`.
2. **בנייה:** מתוך תיקיית הסוכן — `zip -r "/tmp/<name>.plugin" . -x "*.DS_Store"`
3. **שמירה:** `mkdir -p <repo-root>/plugin-builds && cp "/tmp/<name>.plugin" "<repo-root>/plugin-builds/<name>.plugin"`
4. **דיווח:** נתיב, גודל, רשימת קבצים.

> אם את/ה ב-Windows: הפלט ל-`plugin-builds/` בשורש ה-repo (לא ל-Desktop של Mac).

## 6. רישום במרקטפלייס

הוסף ערך למערך `plugins` ב-`<repo-root>/.claude-plugin/marketplace.json`:

```json
{
  "name": "<name>",
  "source": "./agents/ready/<name>",
  "description": "<שם> — משפט קצר."
}
```

⚠️ **אמת JSON תקין אחרי כל עריכה** של `plugin.json` / `marketplace.json` — פסיק חסר או מיותר שובר את טעינת הפלאגין כולו. (אפשר `python3 -m json.tool <file>` לאימות.)

> **בספק על המבנה? פתח סוכן קיים ותקין כתבנית חיה** — סוכן עובד מלא עם `references/`, `commands/`, ו-`plugin.json` תקין. מדגים, לא מתאר (קטלוג א.7).
