# טיקטוק — מצב בדיקת היתכנות (לא בנוי)

## המצב האמיתי (לבדוק שוב לפני כל הנחה — APIs משתנים)

- **הודעות פרטיות (DM):** אין ל-TikTok API ציבורי לניהול הודעות עבור רוב העסקים. יש "TikTok Business Messaging" מוגבל מאוד, לרוב דרך שותפי-פלטפורמה מאושרים (לא גישה ישירה לעסק קטן/בינוני).
- **פרסום תוכן:** יש **Content Posting API** רשמי — אבל: (1) דורש רישום כ-TikTok Developer + יצירת אפליקציה, (2) גישה מלאה (unaudited) מוגבלת ל-Sandbox/בודקים מוגבלים בלבד, (3) גישה מלאה לפרסום אמיתי דורשת **App Review** של טיקטוק — יכול לקחת שבועות ולהידחות.
- **תגובות:** אין endpoint ציבורי מוכר לניהול תגובות בהיקף דומה למטא.

## מה כן אפשרי היום בלי לחכות לאף אישור

- ניסוח תוכן/כיתובים לטיקטוק (כמו `quad-content` עושה לאינסטגרם) — **פרסום ידני** על ידי לאל.
- מעקב אחרי תגובות/הודעות **ידני** — מלאכי יכול לעזור לנסח תשובה שמישהו מדביק בעצמו באפליקציה, בלי גישת API.

## הצעד הראשון האמיתי אם רוצים גישה חיה

1. להירשם ל-TikTok for Developers (developers.tiktok.com), ליצור אפליקציה.
2. לבדוק בפועל איזו רמת גישה מוצעת לחשבון העסקי הספציפי של QUAD (זה משתנה, ולא ידוע מראש).
3. **רק אחרי** שרואים בעיניים מה בפועל אושר — לחזור לבנות את חלק הקוד. לא לפני.

**אל תבטיח "גישה חיה לטיקטוק" למשתמש/ת** — זה תלוי באישור צד-שלישי שאין עליו שליטה, לא רק בזמן פיתוח.
